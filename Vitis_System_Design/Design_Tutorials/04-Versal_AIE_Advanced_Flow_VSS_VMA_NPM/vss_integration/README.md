# VSS Integration: Technical Implementation Guide

This directory implements the complete **VSS→VMA→NPM** integration flow. For project overview and key concepts, see [Root README](../README.md).

## Integration Flow Overview

This implementation demonstrates a 5-step technical integration process:

```
AIE (libadf.a) → VSS → Platform → VMA → Vivado Import → NPM
```

1. **VSS Build** - Integrate AIE graph into Vitis Subsystem (platform-independent)
2. **Platform Build** - Create custom platform with AXI Stream interfaces
3. **VMA Generation** - Export VMA (Vitis Metadata Archive) for Vivado
4. **Vivado Import** - Import VMA into Vivado and add custom RTL
5. **NPM Build** - Build using Vivado Non-Project Mode for advanced control

### Makefile Structure

This directory contains its own Makefile (`vss_integration/Makefile`) that orchestrates the five integration steps. The top-level Makefile (`../Makefile`) coordinates the overall build process:

- **Top-level `make all`**: Builds AIE first, then calls this directory's Makefile
- **Top-level `make vss_integration`**: Directly builds this integration flow (requires AIE to be built first)
- **This directory's `make all`**: Builds all five integration steps in sequence

**Why two Makefiles**: The top-level Makefile manages the entire project (AIE + Integration), while this Makefile focuses specifically on the VSS→VMA→NPM flow. This separation allows you to build the integration steps independently or as part of the complete project.

## Quick Start

### Build Complete Flow

```bash
# Step 1: Build AIE first (from project root)
cd ../aie_dummy
make compile
cd ../vss_integration

# Step 2: Build all integration steps
make all
```

**What happens**: The `make all` command automatically executes all five steps in the correct order: `vss → platform → link_vma → post_link_iteration → npm`. The Makefile handles all dependencies, so you don't need to run each step manually.

**Why build AIE first**: The VSS build requires `libadf.a` (the compiled AIE library). This file is generated by the AIE compilation step and must exist before VSS integration can proceed.

### Build Individual Steps

You can also build individual steps for debugging or incremental development:

```bash
# Build specific steps (dependencies are automatically resolved)
make vss                   # Step 1: VSS build with AIE graph (platform-independent)
make platform              # Step 2: Custom platform with AXI Stream interfaces
make link_vma              # Step 3: Generate VMA (Vitis Metadata Archive)
make post_link_iteration   # Step 4: Import VMA to Vivado and add RTL
make npm                    # Step 5: Build with Vivado Non-Project Mode

# Get help
make help                  # Show all available targets
```

**Why build individual steps**: 
- **Debugging**: If a specific step fails, you can rebuild just that step after fixing issues
- **Incremental development**: After modifying source files, you only need to rebuild affected steps
- **Understanding the flow**: Building step-by-step helps you understand what each stage produces

**Dependency resolution**: The Makefile automatically builds required dependencies.

## Troubleshooting

### Common Issues

1. **`libadf.a` not found**
   ```bash
   # Solution: Build AIE first
   cd ../aie_dummy && make compile
   ```

2. **Platform build fails**
   - Verify VEK280 base platform is available in your Vitis installation
   - Check platform path in `platform/hw/xsa_scripts/`

3. **VMA generation fails**
   - Ensure both VSS (`vss/vss/vss_ss.vss`) and platform (`platform/hw/build/hw.xsa`) are built successfully
   - Check `link_vma/system.cfg` for correct paths

4. **Vivado import errors**
   - Verify VMA file exists: `link_vma/post_link.vma`
   - Check Vivado version compatibility (2025.2+)

5. **NPM build fails**
   - Ensure post_link_iteration step completed successfully
   - Check `npm/vivado_npm.tcl` script for correct paths

### Clean Build

```bash
# Clean all build artifacts
make clean

# Clean specific component
make -C vss clean
make -C platform/hw clean
make -C link_vma clean
make -C post_link_iteration clean
make -C npm clean
```
